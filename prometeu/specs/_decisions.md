# Decisions

The repository memory. Injected at the start of every session next to
`_context.md`, so no session re-litigates what a previous one settled.

`_context.md` holds facts about the code and is regenerated by a script.
This file holds choices about it and is written by hand, one entry per
decision, newest first. Never delete an entry: mark it superseded and point
forward.

When an entry is cited in three sessions, it has become a rule. Promote it to
the instruction file whose `applyTo` matches, and leave a one-line pointer here.

All entries below were taken in the design session that produced the spec set,
before the application repository existed. They bind every `plan.md` in
`prometeu/specs/`.

---

## 2026-09-17 · Plans written before the repository exists cite planned paths and confirm them first

Session: 000-design

Rejected: waiting for the repository to write plans — it would serialise twenty
specify phases behind one scaffold.

Constrains: "Reuse found" cites files as "planned in NNN-slug"; step 1 of every
order of work is "confirm the reused files exist as described; if not, return
blocked". Every plan lists the shared files it modifies (rail, header,
`src/server/db/schema/index.ts`, workspace creation) so the unrequested-change
check stays clean.

## 2026-09-17 · Environment variables are validated at startup and listed in `.env.example` with empty values

Session: 000-design

Rejected: reading `process.env` at the call site — a missing variable then
fails on the first request that needs it, not at boot.

Constrains: `DATABASE_URL`, `DATABASE_URL_TEST`, `AUTH_SECRET`, provider-specific
`AUTH_*`, `LLM_PROVIDER`, `AWS_REGION`, `BEDROCK_MODEL_ID`; AWS credentials via
the default chain. Startup names the missing variable, never its value. No
model id, key or connection string in source.

## 2026-09-17 · Sanctioned commands are the ones in `_context.md` and nothing else

Session: 000-design

Rejected: letting each plan invent scripts — the `_context.md` table is what
agents may run.

Constrains: `npm ci`, `npm run build`, `npm test`, `npx vitest run <path>`,
`npm run lint` (eslint + `tsc --noEmit`), `npm run test:e2e`,
`docker compose up -d db`, `npm run db:migrate`, `npm run dev`, the
traceability command. `db:generate` is a plan step, `db:rollback` is Q3, deploys
are never run by an agent.

## 2026-09-17 · Tests: Vitest + Testing Library, Playwright + axe, real Postgres, fake LLM, fake clock; every test name starts with the full requirement id

Session: 000-design

Rejected: Jest (slower with ESM and TS), mocking the database (repository bugs
are exactly what the mock hides).

Constrains: unit tests co-located as `*.test.ts(x)`; e2e in `tests/e2e/*.spec.ts`,
one file per spec directory; repository tests run against `DATABASE_URL_TEST`
with truncation between tests; the LLM provider in tests is `fake`; time is
injected. `it("FR-00301 selects rows by exact period", …)` — one id per test,
id first.

## 2026-09-17 · Logging is a JSON-lines wrapper that never logs secrets or content; rate limiting is in-memory per instance

Session: 000-design

Rejected: a logging framework (no consumer asked for one); a shared rate-limit
store (no multi-instance hosting decided yet).

Constrains: `src/server/log.ts`; never tokens, session ids, document contents or
prompts. Multi-instance hosting needs a shared store — tied to the hosting open
question in 001-app-skeleton.

## 2026-09-17 · pt-BR strings are inline constants; no i18n framework

Session: 000-design

Rejected: next-intl — no second language was requested.

Constrains: engine and formula error messages are pt-BR constants inside
`src/core`; UI strings live next to the component that shows them.

## 2026-09-17 · One LLM provider interface in `src/server/llm`, adapters selected by `LLM_PROVIDER`

Session: 000-design

Rejected: calling a vendor SDK from the assistant route — the user asked for
either AWS Bedrock or the user's Copilot, so the seam is required.

Constrains: `LlmProvider.complete({ system, messages, tools, maxTokens, signal })`
returns text and tool calls; adapters `bedrock.ts` (Converse API), `fake.ts`,
`copilot.ts` (020-copilot-provider, blocked on open questions). Model ids only in
env. Every call carries an `AbortSignal` timeout. The model only proposes; the
application validates with `src/core/schema` and the user confirms.

## 2026-09-17 · File parsing runs on the server only

Session: 000-design

Rejected: parsing in the browser as the prototype did — the file must reach the
server anyway to persist rows, and one validation path is cheaper than two.

Constrains: `src/server/import`; CSV/TXT parser ported by hand (small); XLSX via
a library reading the first sheet — the planner of 008 picks between `exceljs`
and SheetJS once (flag: SheetJS is more common, its npm cadence and licence are
the concern).

## 2026-09-17 · The engine runs on the client in the studio and on the server for export and assistant context

Session: 000-design

Rejected: computing every chart on the server — a round-trip per property change
on a canvas of up to 100 widgets.

Constrains: the rows endpoint returns the full bounded set of a source in the
collection envelope; real pagination arrives with the SAP connector.

## 2026-09-17 · Styling is CSS Modules plus `src/styles/tokens.css` porting the prototype's variables

Session: 000-design

Rejected: Tailwind (would re-express every prototype rule); CSS-in-JS (server
render cost).

Constrains: tokens navy `#0b1354`, blue `#1643db`, rail 64px, header 52px,
explorer 212px, inspector 284px, toolbar 48px; breakpoints ≥1600, ≤1300, ≤1100,
≤760; fonts DM Sans and Manrope via `next/font`; focus ring visible.

## 2026-09-17 · Charts are custom SVG React components with no chart library

Session: 000-design

Rejected: Recharts or D3 — the prototype's look is bespoke, and the HTML export
needs static markup rendered on the server.

Constrains: `src/ui/charts`, one renderer per widget type, width from a
ResizeObserver, data from `src/core/engine`, renderable with `renderToStaticMarkup`.

## 2026-09-17 · Client state is one zustand store per open analysis; undo/redo is whole-document snapshots in memory; autosave uses `revision`

Session: 000-design

Rejected: command-pattern undo (more code, no benefit at ≤100 widgets); Redux
Toolkit (heavier); React Query (one document, no cache invalidation problem).

Constrains: store holds document, selection, active page, history (max 30),
dirty and save state; every mutation is a store action; autosave debounces 1 s,
sends `revision`, and on 409 shows a conflict toast offering reload. Undo is not
persisted or synced across tabs.

## 2026-09-17 · Naming: `revision` for concurrency, `versions` for named snapshots, `schemaVersion` for the document format

Session: 000-design

Rejected: the prototype's `pro.version` — it collides with named versions.

Constrains: database ids are UUIDs from `crypto.randomUUID()`; timestamps
`timestamptz`; row dates stay `YYYY-MM-DD` strings; soft delete via
`deleted_at`; document-internal ids keep the prototype formats.

## 2026-09-17 · `src/core/schema` (zod) is the single source of truth for validation; boundaries reject, never clamp

Session: 000-design

Rejected: keeping the prototype's coercing sanitizer (`cleanPro`) — it hides bad
clients and violates "no unvalidated boundary input".

Constrains: every boundary (handlers, import, LLM output, client apply) parses
with the schema and returns the field path on failure; internal types are
`z.infer`; UI controls clamp before sending; widget defaults fill missing keys
for a *new* widget only.

## 2026-09-17 · Auth.js with database sessions; one authorization matrix with `assertCan(actor, action, resource)`

Session: 000-design

Rejected: per-analysis ACLs — not asked for; recorded as an open question in
017-presentation-and-export. Hand-typed roles table on the governance page — it
would drift from enforcement.

Constrains: roles `reader | editor | admin` in code, labels Leitor / Editor /
Administrador in the UI; membership of the object's workspace is checked on every
request, never a client-supplied role; the governance page renders its table from
the matrix. The identity provider is 005-authentication's open question. All of
this is Q4.

## 2026-09-17 · PostgreSQL with Drizzle ORM and committed SQL migrations, additive only

Session: 000-design

Rejected: Prisma — generated client and no down migrations. Acceptable if the
team already runs it; this is a preference, flagged.

Constrains: `src/server/db/migrations/NNNN_name.sql` with a hand-written
`NNNN_name.down.sql` and its data-loss note beside it; expand/contract for
anything breaking; local database via docker-compose; tests and CI against a
real Postgres.

## 2026-09-17 · API style is Route Handlers returning JSON with one error envelope

Session: 000-design

Rejected: Server Actions — implicit endpoints, harder to contract-test with a
plain `Request`, and the future SAP connector and external clients need explicit
HTTP contracts anyway.

Constrains: `{ error: { code, message, field? } }` with stable snake_case codes
and pt-BR messages; collections `{ data, nextCursor }` with `limit ≤ 100`; Server
Components read initial data through the same repository functions; every
mutation goes through a handler.

## 2026-09-17 · Directory layout and pt-BR route paths

Session: 000-design

Rejected: English route paths — the product language is pt-BR and the
prototype's hash routes are already these words.

Constrains:

```
src/app/                 App Router; route groups (shell) and (auth); api/**/route.ts
src/core/schema          zod schemas + z.infer types
src/core/engine, formula, format, demo, scenario
src/server/db            client, schema/*.ts one file per spec, migrations/
src/server/auth, authz, repos, import, export, llm, http, log.ts, env.ts
src/ui/shell, charts, studio, library, sources, planning, governance, home, assistant
src/styles/tokens.css, globals.css
tests/e2e/*.spec.ts      Playwright; unit tests co-located *.test.ts(x)
```

Routes: `/inicio`, `/dashboard/[analysisId]`, `/dashboards`, `/dados`,
`/planejamento`, `/governanca`, `/produto`, `/entrar`; `/` redirects to the most
recently updated analysis or an empty state.

## 2026-09-17 · One Next.js application, no monorepo; `src/core` purity enforced by lint

Session: 000-design

Rejected: a pnpm workspace with a `core` package — adds tooling for a single
consumer.

Constrains: an ESLint `no-restricted-imports` rule forbids `react`, `next`,
`node:*`, `src/server` and `src/ui` inside `src/core`, so the engine, schema and
formula modules run identically on server and client.

## 2026-09-17 · Requirement ids use the `FR-NNNSS` / `NFR-NNNSS` scheme and never restart per spec

Session: 000-design

Rejected: restarting at `FR-001` in every spec — the traceability tool's
coverage map is repository-wide, so one spec's test would mark every spec's
`FR-001` as verified. `FR-301`-style prefixes — variable width becomes
ambiguous past spec 099.

Constrains: `NNN` = spec directory number, `SS` = sequence; a `spec.md` never
mentions another spec's id (cross-reference by directory name); the id goes
first in every test name and one test cites one id.
